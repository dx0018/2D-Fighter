# 口袋对决 · Pocket Clash

一款可以在同一台电脑上用键盘对战的网页 2.5D 格斗游戏。包含主页、双人选人、选场地、正式对战、胜负结算与再战。首发角色是哆啦A梦与天线宝宝小波，可同角色对战；三个场地分别是口袋街角、落日天台和月光花园。

仓库起初没有可访问的旧游戏代码或美术资源，因此本版从零重建。角色、场景和特效采用 Three.js 程序化卡通 3D，立绘与地图预览由 SVG 绘制，无需外部模型或图片服务。浏览器无法创建 WebGL 时自动使用 Canvas 兼容画面，战斗逻辑继续工作。

## 启动

需要 Node.js 20.19+ 或 22.12+（当前开发使用 Node.js 24）与 npm。

```bash
cd /workspace/2D-Fighter
npm ci
npm run dev
```

在浏览器打开 Vite 输出的地址，默认端口为 `5173`。开发服务器监听 `0.0.0.0`，可以通过工作环境的端口预览入口访问。若端口被占用，Vite 会输出实际端口。

```bash
npm run build    # 生成 dist/ 生产静态文件
npm run preview  # 本地预览生产构建，默认端口 4173
npm test         # 运行 DOM 无关的战斗引擎测试
```

浏览器端到端检查使用系统 Chromium；先在一个终端运行 `npm run dev`，再在另一个终端运行：

```bash
TEST_URL=http://localhost:5173 npm run test:e2e
TEST_URL=http://localhost:5173 npm run test:compat  # 无 WebGL 兼容模式与完整招式检查
```

脚本默认浏览器路径为 `/usr/bin/chromium`，可用 `CHROMIUM_PATH=/你的/chromium/路径` 指定其它 Chromium。若 Vite 使用其它端口，请同步调整 `TEST_URL`。截图保存在忽略追踪的 `artifacts/` 目录中。

`dist/` 可以部署到支持静态文件的网页托管服务。无需数据库、账号、后端或 API 密钥。初次安装需要访问 npm；安装完成后运行游戏无需网络资源请求。

## 操作与流程

点击「开始游戏」，分别为 P1 和 P2 选择角色并确认。选择地图，或点击随机选图后查看最终选中的地图，再点击「准备开战」。三秒倒数结束后开始对战。

| 动作        | P1    | P2    |
| ----------- | ----- | ----- |
| 左右移动    | A / D | ← / → |
| 跳跃        | W     | ↑     |
| 蹲下        | S     | ↓     |
| 普攻        | F     | J     |
| 技能        | G     | K     |
| 大招        | H     | L     |
| 暂停 / 继续 | Esc   | Esc   |

招式和跳跃由一次按下触发，松开再按才能再次触发，长按不会自动连发。移动与蹲下可持续按住。方向键在对战中会阻止页面滚动。失去窗口焦点时自动暂停，避免切回页面时角色仍在移动。较窄屏幕可展开屏幕操作面板；同机双人建议使用键盘。

- **胜负**：一局 99 秒，任一方生命归零即结束；超时按剩余生命比例判定，双 KO 或比例相同为平局。结算后可以沿用角色与地图再战、重新选人或返回主页。
- **能量**：开局 100 EP，每秒恢复 5 EP。技能消耗 24 EP，大招消耗 70 EP；普攻命中恢复 12 EP，受击恢复 7 EP。HUD 同时显示能量、冷却和可用状态。
- **哆啦A梦**：圆圆拳为近距离攻击；空气炮为远程投射物，可通过蹲下或跳跃躲避；未来光束蓄力后朝出招时的方向释放，射程远。
- **小波**：快乐拍击擅长近身；滑步冲撞可快速接近；快乐大爆发在蓄力后攻击身体两侧一定范围。
- **打击**：招式有前摇、有效窗口和后摇；同次招式不会反复扣血。命中带有受击硬直、击退、闪光、粒子与轻微镜头震动。同帧有效的攻击可以互相命中。
- **场景互动**：木箱受到足够伤害后碎裂并消失；招牌受击摇晃后恢复。再战会恢复场景对象。它们不会阻挡玩家走位。
- **音效**：首次点击后可播放浏览器合成音效；右上角音符开关控制音效。

不同实体键盘的按键冲突能力不同；若特定多键组合未被硬件识别，可用屏幕操作面板补充输入。

## 项目结构

```text
src/
  main.js                 页面状态、选择流程、HUD、结算与暂停
  style.css               响应式界面与布局
  config/content.js       角色、招式与地图配置
  game/
    engine.js             独立战斗模拟、命中和对象互动
    input.js              两位玩家键盘与触屏输入
    audio.js              Web Audio 合成音效
    contract.md           引擎、配置和渲染器接口
  render/
    arena.js              3D 场景、角色、动画、镜头与 Canvas 兼容绘制
    portraits.js          程序化 SVG 立绘与地图预览
tests/
  engine.test.js           战斗规则回归测试
  browser.mjs              完整流程、真实输入与响应式检查
  browser-compat.mjs       Canvas 回退、六个攻击键与地图互动检查
```

`Game` 不依赖 DOM 或渲染器，通过 `step(dt, inputs)` 推进状态，渲染器读取 `game.state`。输入只在对战阶段启用，倒数、暂停和结算由独立状态控制。效果对象具有生命周期，地图互动对象的运行状态与原始配置分离，因此每次再战都可以完整重置。

## 扩展角色与招式

在 `src/config/content.js` 的 `characters` 数组中新增角色。角色配置包含 ID、中英文名称、介绍、主题色、基础属性、最大生命与能量、移动速度、跳跃初速度、模型样式和三个招式。

每个招式配置包含名称、说明、伤害、距离、前摇、有效时长、后摇、冷却、能量消耗、击退、硬直和特效颜色。现有行为类型为：

| `kind`       | 行为                     | 额外参数                              |
| ------------ | ------------------------ | ------------------------------------- |
| `melee`      | 朝面前的近身攻击         | `range`                               |
| `projectile` | 发射独立投射物           | `projectileSpeed`、`radius`、`height` |
| `dash`       | 在有效阶段朝出招方向冲刺 | `dashSpeed`                           |
| `beam`       | 朝出招方向的长距离光束   | `range`                               |
| `pulse`      | 身体两侧的范围攻击       | `range`                               |

新角色可以复用以上行为并调整数值；全新行为需要在引擎 `release` / `collectStrike` 中增加处理。选角界面、角色详情、技能栏和对局创建都会读取列表，不需逐个添加按钮。

模型通过 `bodyStyle` 选择程序化构建器。`src/render/arena.js` 导出 `registerFighterModel(bodyStyle, builder)`，可为新角色注册模型构建器；同步增加对应立绘，可获得独立的角色外观。未知模型样式会使用现有程序化模型作为可运行替代。`model` 字段目前为未来外部资源预留，本版不加载 Blender / GLTF 文件。

以后添加方向招式时，可以扩展输入对象与角色招式表，再在 `beginMove` 前解析组合；当前普攻、技能和大招均保留独立按键与配置。

## 扩展地图与互动对象

在 `maps` 数组新增地图即可自动进入选图界面。每张地图包含：

- `id`、名称、介绍、标签与 `preview` 元数据。
- `theme` 与 `colors`，用于场景和预览；现有主题为 `town`、`sunset`、`moon`。
- `bounds.left/right`，定义战斗边界。
- `spawns`，分别定义双方出生点与朝向。
- `camera`，定义初始位置、最小/最大可视宽度与镜头左右限制。
- `objects`，定义互动对象 ID、类型、世界坐标、宽高、耐久和颜色。

地图坐标使用世界单位，地面 `y = 0`；角色沿 `x` 轴移动，通过 `y` 跳跃。将出生点放在边界内，并为双方留出初始距离。镜头根据双方位置平滑缩放与移动；窄屏保持足够横向可视范围。

现有对象类型是 `crate` 和 `sign`。木箱按照 `hp` 累计受伤后破坏；招牌不会被摧毁，受击会产生衰减摇晃。新增物件类型需要同时补充引擎受击行为和渲染构建逻辑。全新的场景主题也需要在场景构建器和预览绘制中增加美术实现。

## 验证范围

引擎测试覆盖攻击距离、单次判定、同时攻击、双 KO、能量与冷却、跳跃重复输入、蹲下躲避投射物、边界、技能差异、木箱与招牌、暂停、重置、超时及生命比例判定。浏览器流程测试覆盖实际键盘事件、页面按钮、HUD、再战、桌面与 390px 响应式布局。兼容模式测试在禁用 WebGL 后验证六个攻击按键、实际伤害、木箱破坏、招牌摇晃与触屏跳跃。KO 流程测试通过调整血量和站位缩短等待，再由真实按键触发命中与结算。
