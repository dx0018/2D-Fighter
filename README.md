# 口袋对决 · Pocket Clash

一款可以在同一台电脑上用键盘对战的网页 2.5D 格斗游戏。包含主页、双人选人、选场地、正式对战、胜负结算与再战。首发角色是哆啦A梦与天线宝宝小波，可同角色对战；三个场地分别是口袋街角、落日天台和月光花园。

仓库起初没有可访问的旧游戏代码或美术资源，因此本版从零重建。角色、场景和特效采用 Three.js 程序化卡通 3D，角色关节动画、物理材质与透视镜头均在浏览器实时渲染；立绘与地图预览由同一套模型离线渲染成 WebP，缺失时回退为 SVG，无需外部模型或图片服务。浏览器无法创建 WebGL 时自动使用 Canvas 兼容画面，战斗逻辑继续工作。

## 启动

需要 Node.js 20.19+ 或 22.12+（当前开发使用 Node.js 24）与 npm。

```bash
cd /workspace/2D-Fighter
npm ci
npm run dev
```

在浏览器打开 Vite 输出的地址，默认端口为 `5173`。开发服务器监听 `0.0.0.0`，可以通过工作环境的端口预览入口访问。若端口被占用，Vite 会输出实际端口。

```bash
npm run build    # 生成 dist/ 生产静态文件
npm run preview  # 本地预览生产构建，默认端口 4173
npm test         # 战斗引擎与透视镜头回归测试
```

浏览器端到端检查使用系统 Chromium；先在一个终端运行 `npm run dev`，再在另一个终端运行：

```bash
TEST_URL=http://localhost:5173 npm run test:e2e
TEST_URL=http://localhost:5173 npm run test:compat  # 无 WebGL 兼容模式与完整招式检查
TEST_URL=http://localhost:5173 npm run test:visual  # 三张地图、全部招式的 WebGL 画面检查
TEST_URL=http://localhost:5173 npm run test:directional  # 十种技能的真实按键、蹲姿与招式表
TEST_URL=http://localhost:5173 npm run test:experience   # 中英文切换、对局保留、高刷节奏与窄屏
```

脚本默认浏览器路径为 `/usr/bin/chromium`，可用 `CHROMIUM_PATH=/你的/chromium/路径` 指定其它 Chromium。若 Vite 使用其它端口，请同步调整 `TEST_URL`。截图保存在忽略追踪的 `artifacts/` 目录中。

`dist/` 可以部署到支持静态文件的网页托管服务。无需数据库、账号、后端或 API 密钥。初次安装需要访问 npm；安装完成后运行游戏无需网络资源请求。

## 操作与流程

点击「开始游戏」，分别为 P1 和 P2 选择角色并确认。选择地图，或点击随机选图后查看最终选中的地图，再点击「准备开战」。三秒倒数结束后开始对战。

页面顶部的语言选择器可随时切换「中文 / English」，并在下次打开时记住选择。菜单、角色与地图介绍、招式表、冷却提示、暂停和结算均会切换。语言切换只更新界面文字，保留角色选择、地图、生命、冷却和正在进行的对局。

| 动作        | P1    | P2    |
| ----------- | ----- | ----- |
| 左右移动    | A / D | ← / → |
| 跳跃        | W     | ↑     |
| 蹲下        | S     | ↓     |
| 普攻        | F     | J     |
| 技能        | G     | K     |
| 大招        | H     | L     |
| 暂停 / 继续 | Esc   | Esc   |

招式和跳跃由一次按下触发，松开再按才能再次触发，长按不会自动连发。移动与蹲下可持续按住。方向键在对战中会阻止页面滚动。失去窗口焦点时自动暂停，避免切回页面时角色仍在移动。较窄屏幕可展开屏幕操作面板；同机双人建议使用键盘。

- **胜负**：一局 99 秒，任一方生命归零即结束；超时按剩余生命比例判定，双 KO 或比例相同为平局。结算后可以沿用角色与地图再战、重新选人或返回主页。
- **能量**：开局 100 EP，每秒恢复 5 EP。技能消耗 24 EP，大招消耗 70 EP；普攻命中恢复 12 EP，受击恢复 7 EP。HUD 同时显示能量、冷却和可用状态。
- **哆啦A梦**：圆圆拳为近距离攻击；空气炮从伸直手炮以胸口高度发射，跳跃可躲避；未来光束蓄力后朝出招时的方向释放，射程远。
- **小波**：原地从天线释放光线，向前以滑步冲撞接近，后退、下蹲与空中有不同技能；快乐大爆发蓄力后攻击身体两侧。
- **方向招式**：G / K 根据按下瞬间的方向与姿态选择，HUD 显示当前招式，对战页和操作说明中可展开招式表。前／后相对敌人，双方换边后自动对应。空中优先于下蹲与前后方向；跳跃＋技能可以同时按。五种技能共用冷却，H / L 大招独立。F / J 另有下蹲扫腿和空中飞踢。
- **打击**：招式有前摇、有效窗口和后摇；同次招式不会反复扣血。命中带有受击硬直、击退、闪光、粒子与轻微镜头震动。同帧有效的攻击可以互相命中。普攻／技能／大招分别有 55–120ms 的命中停顿；普攻保留 180ms 提前输入，其他招式为 120ms。下一拳仍等待收招和冷却结束。命中停顿不会重复伤害；持续按住不会连发。连击计数、血条残影和大招名称会随状态显示。
- **场景互动**：木箱受到足够伤害后碎裂并消失；招牌受击摇晃后恢复。再战会恢复场景对象。它们不会阻挡玩家走位。
- **音效**：首次点击后可播放浏览器合成音效；右上角音符开关控制音效。

不同实体键盘的按键冲突能力不同；若特定多键组合未被硬件识别，可用屏幕操作面板补充输入。

| 技能输入          | 哆啦A梦 G  | 小波 K   | 主要用途                                   |
| ----------------- | ---------- | -------- | ------------------------------------------ |
| 原地              | 空气炮     | 天线光线 | 远程牵制；天线光线从头顶斜射，释放后不追踪 |
| 朝敌人移动        | 推进拳套   | 滑步冲撞 | 接近敌人，落空后留出收招空隙               |
| 远离敌人          | 后撤空气炮 | 回旋退步 | 拉开距离；回旋退步释放时短暂闪避           |
| 下蹲              | 贴地空气弹 | 贴地滑踢 | 低位攻击，能命中蹲姿，可被跳过             |
| 空中 / 跳跃＋技能 | 俯冲空气炮 | 空中回旋 | 斜下射击与空对空；落地取消未完成的空中招式 |

胸口高度空气炮可以跳跃躲避，天线光线可以蹲下躲避，低位弹和扫腿可以被跳过。按键缓冲保留按下时选择的方向，避免松开方向后意外换招。蹲姿技能在前后摇中保持低姿态。

角色使用骨骼蒙皮与固定长度的双骨 IK。走跑按实际横向位移推进，支撑脚锁定在地面，包含屈膝、摆腿与反向摆臂；反向移动会反向推进步态，抬脚落脚使用连续曲线，松键后逐渐收回脚步。普攻使用连续的蓄力、伸手与回到待机姿势曲线，哆啦A梦直拳和小波拍击具有不同路线。蹲姿通过髋部下降和躯干前倾完成，头部、躯干保持原比例；脸和腹部贴合主体表面。地面移动、转向和松键停止在下一个模拟步生效；跳跃准备为 25ms，包含空中收腿和落地缓冲。

右上角可选择「自动／精细／流畅」画质，并记住选择。对战动画、输入和模拟跟随浏览器刷新，不再把高刷屏画面强制跳帧到 60fps；HUD 文字独立限制为每秒 30 次更新，阶段变化立即显示。自动模式在持续低于约 52fps 或软件渲染时降低绘制分辨率和动态阴影负担。街景减少远处树叶和建筑倒角的细分，连续攻击复用有容量上限的特效资源。暂停时保持画面，调整窗口大小会重绘；主页预览限制为 30fps。低于 20fps 时模拟不再额外减速，长时间切出窗口仍会暂停。

普攻命中停顿缩短为 28／34ms，保留击退与命中反馈；冷却为 0.42／0.52 秒。直拳与拍击在后摇的最后 45% 可恢复地面移动，攻击本身仍正常完成，持续按键仍不会自动连发。起步第一帧即可落脚支撑，摆腿从实际离地点过渡，自由脚在世界坐标平滑，空中姿势继续跟随身体。

## 项目结构

```text
src/
  main.js                 页面状态、选择流程、HUD、结算与暂停
  style.css               响应式界面与布局
  config/content.js       角色、招式与地图配置
  i18n/
    index.js              语言保存、动态文案与保留 DOM 的语言切换
    en.js                 菜单、角色、地图和招式的英文文案
  game/
    engine.js             独立战斗模拟、命中和对象互动
    frame-time.js         帧时间策略与长停顿限制
    moves.js              相对方向、姿态招式选择与招式表
    collision.js          斜向射线／投射物的连续判定
    input.js              两位玩家键盘与触屏输入
    audio.js              Web Audio 合成音效
    contract.md           引擎、配置和渲染器接口
  render/
    arena.js              渲染生命周期、灯光、环境反射与阴影
    fighters.js           两个卡通角色模型与关节结构
    rig.js                骨骼蒙皮、固定肢长双骨 IK
    animation.js          待机、步态、前后摇、受击与胜利姿势
    locomotion.js         连续步态、前后移动与起停混合
    melee-motion.js       对齐命中窗口的普攻蓄力、出手和收招曲线
    stages.js             分层场景、地面材质与互动对象
    camera.js             透视取景、跟随、边界和缩放
    effects.js            蓄力环、光束、震波、拖尾与碎片
    primitives.js         几何工具、材质、静态合批和资源释放
    surface-batching.js   保留颜色与表面属性的场景合批
    static-shadows.js     静态阴影缓存
    quality.js            画质预设和持续慢帧降级
    fallback.js           无 WebGL 的 Canvas 兼容绘制
    portraits.js          WebP 预览与 SVG 错误回退
public/previews/          与实际模型一致的角色和地图预览
scripts/render-previews.mjs  重新生成预览资源
scripts/inspect-motion.mjs  六种姿势的角色检查图
scripts/inspect-flow.mjs    双角色起停、反向与普攻连续预览视频
scripts/profile.mjs         同一视口下的软件渲染采样
tests/
  engine.test.js           战斗规则、命中停顿和按键缓冲回归
  directional.test.js      五种技能、前后换边、高低位与空中判定
  animation.test.js        蹲姿高度、地面接触、支撑脚与暂停姿势
  responsiveness.test.js  即时起停、25ms 起跳与不同帧率的模拟一致性
  quality.test.js         画质降级、选择保留与防止反复切换
  camera.test.js           三种画幅下的边界、跳跃与快速分离检查
  browser.mjs              完整流程、真实输入与响应式检查
  browser-compat.mjs       Canvas 回退、六个攻击键与地图互动检查
  visual-upgrade.mjs       新场景、招式和窄屏 HUD 实际渲染检查
  directional-browser.mjs  十种技能真实按键、双人蹲姿与招式表
  experience-browser.mjs   双语流程、切换保留对局、原生刷新节奏与特效复用
```

`Game` 不依赖 DOM 或渲染器，通过 `step(dt, inputs)` 推进状态，渲染器读取 `game.state`。输入只在对战阶段启用，倒数、暂停和结算由独立状态控制。效果对象具有生命周期，地图互动对象的运行状态与原始配置分离，因此每次再战都可以完整重置。

## 扩展角色与招式

在 `src/config/content.js` 的 `characters` 数组中新增角色。角色配置包含 ID、中英文名称、介绍、主题色、基础属性、最大生命与能量、移动速度、跳跃初速度、模型样式和三个招式。

每个招式配置包含名称、说明、伤害、距离、前摇、有效时长、后摇、冷却、能量消耗、击退、硬直和特效颜色。`impact.stop` 和 `impact.shake` 分别配置命中停顿时长与镜头震动幅度。现有行为类型为：

| `kind`       | 行为                     | 额外参数                              |
| ------------ | ------------------------ | ------------------------------------- |
| `melee`      | 朝面前的近身攻击         | `range`                               |
| `projectile` | 发射独立投射物           | `projectileSpeed`、`radius`、`height` |
| `dash`       | 在有效阶段朝出招方向冲刺 | `dashSpeed`                           |
| `beam`       | 朝出招方向的长距离光束   | `range`                               |
| `pulse`      | 身体两侧的范围攻击       | `range`                               |

新角色可以复用以上行为并调整数值；全新行为需要在引擎 `release` / `collectStrike` 中增加处理。选角界面、角色详情、技能栏和对局创建都会读取列表，不需逐个添加按钮。

模型通过 `bodyStyle` 选择程序化构建器。`src/render/arena.js` 导出 `registerFighterModel(bodyStyle, builder)`，可为新角色注册模型构建器；新增 `previewImage` 后，在运行开发服务器时执行 `node scripts/render-previews.mjs` 可重新生成与模型一致的立绘及地图预览。生成器使用本地 Chromium，输出到 `public/previews/`。未知模型样式会使用现有程序化模型作为可运行替代。`model` 字段目前为未来外部资源预留，本版不加载 Blender / GLTF 文件。

方向招式在基础招式的 `variants` 中配置 `forward`、`backward`、`crouch`、`air`。未覆盖的属性继承基础招式；可覆盖名称、数值、`kind` 与 `animation`。`posture: 'crouch'` 保持低姿态，`hitY/hitHeight` 指定近身或范围判定，`height/angle` 指定出射位置和斜角，`movement` 指定有效段相对移动速度，`gravityScale` 调整空中招式重力。变体共享按键槽冷却，无需新增按键或页面按钮。

普攻可设置 `recoveryMovement`（0～1），指定后摇进行到何时恢复站立地面移动；不影响技能、蹲姿与空中招式。新增内容的中文名称、介绍与招式说明应同步补充到 `src/i18n/en.js`，未翻译的文案会显示原文。

## 扩展地图与互动对象

在 `maps` 数组新增地图即可自动进入选图界面。每张地图包含：

- `id`、名称、介绍、标签与 `preview` 元数据。
- `theme` 与 `colors`，用于场景和预览；现有主题为 `town`、`sunset`、`moon`。
- `bounds.left/right`，定义战斗边界。
- `spawns`，分别定义双方出生点与朝向。
- `camera`，定义初始位置、最小/最大可视宽度与镜头左右限制。
- `objects`，定义互动对象 ID、类型、世界坐标、宽高、耐久和颜色。

口袋街角、落日天台、月光花园的可移动宽度分别为 58、64、60 个世界单位，镜头并非一次显示整个场地。地图坐标使用世界单位，地面 `y = 0`；角色沿 `x` 轴移动，通过 `y` 跳跃。将出生点放在边界内，并为双方留出初始距离。透视镜头根据双方位置平滑缩放与移动，并为跳跃高度与快速分离留出安全边距；窄屏保持足够横向可视范围。场景通过远近层次、真实地面、接触阴影、反射和灯光表现纵深，战斗移动仍沿同一横向平面。

现有对象类型是 `crate` 和 `sign`。木箱按照 `hp` 累计受伤后破坏；招牌不会被摧毁，受击会产生衰减摇晃。新增物件类型需要同时补充引擎受击行为和渲染构建逻辑。全新的场景主题也需要在场景构建器和预览绘制中增加美术实现。

## 验证范围

引擎测试覆盖攻击距离、单次判定、同时攻击、双 KO、能量与冷却、跳跃重复输入、蹲下躲避投射物、边界、技能差异、木箱与招牌、暂停、重置、超时及生命比例判定。浏览器流程测试覆盖实际键盘事件、页面按钮、HUD、再战、桌面与 390px 响应式布局。兼容模式测试在禁用 WebGL 后验证六个攻击按键、实际伤害、木箱破坏、招牌摇晃与触屏跳跃。KO 流程测试通过调整血量和站位缩短等待，再由真实按键触发命中与结算。

## 视觉升级说明

角色采用带骨骼蒙皮的程序化卡通模型：哆啦A梦的柔和外壳、金属铃铛与随手臂运动的空气炮，小波的布偶材质、柔性天线和发光屏幕。动画读取实际招式前摇、有效段和后摇；特效在有效段释放，受击停顿期间保持接触姿势。暂停时冻结动画与特效。浏览器的「减少动态效果」设置会关闭镜头震动与边缘闪光。

场景使用顶点颜色及表面属性合批，静态阴影以 1024 贴图缓存，动态阴影仅处理角色与互动对象。精细模式动态阴影为 1024、像素比上限 1.5；自动模式上限 1.25，慢帧时降低到流畅模式的 0.75 并使用接触阴影。粒子按几何实例化绘制，HUD 缓存节点并逐帧更新，空闲状态不重复改写页面。招式纹理与音效在本地生成。

模型参考与性能记录见 [建模、动作与性能](docs/model-motion-performance.md)。开发服务器运行时，可用 `npm run inspect:motion` 生成姿势检查图，`npm run inspect:flow` 生成走路与普攻预览视频（需 FFmpeg），`npm run profile` 输出软件渲染对比数据；这类采样用于同环境比较，不代表设备实际帧率。截图、视频和采样文件均放在忽略追踪的 `artifacts/`。

当前游戏性检查与后续优先级见 [对战体验检查](docs/gameplay-review.md)。
