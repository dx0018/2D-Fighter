# 建模、动作与性能

## 参考来源

- [Quaternius / Tomás Laulhé 的 RobotExpressive](https://github.com/mrdoob/three.js/tree/r181/examples/models/gltf/RobotExpressive)，CC0 1.0。实际读取了 GLB 的 Walking、Sitting、Jump 动画和骨骼层级，离线渲染了姿势作比较。参考髋部、躯干、头部层级，以及固定肢长的屈膝；游戏角色的几何与动作在本项目中生成。
- [Three.js 角色 IK 示例](https://github.com/mrdoob/three.js/blob/r181/examples/webgl_animation_skinning_ik.html)，参考关节目标与旋转限制的组织方式。
- [Three.js 动画混合示例](https://github.com/mrdoob/three.js/blob/r181/examples/webgl_animation_skinning_blending.html)，参考动作权重过渡。输入直接进入战斗模拟，过渡仅作用于视觉姿态。

## 实现变化

旧实现通过拉伸胶囊连接关节，并压缩躯干、反向放大头部来蹲下，导致肢长和体积变化。现在上臂、前臂、大腿、小腿使用固定长度骨骼和蒙皮，IK 对不可达目标限幅；身体与脸的比例保持不变。头和腹部是贴合主体的曲面，减少浮起的脸片和腹片。躯干沿身体前后方向屈髋，肩膀保持同高；支撑脚锁在世界坐标，转向和反向移动时不会突然换位。姿势检查还验证了胸前屏幕、腹部和脚不会穿过地面。

即时起停和反向移动在下一模拟步执行；起跳准备从 75ms 调整到 25ms，保留空中收腿和落地缓冲。原先帧时间上限 50ms 会使 15fps 下游戏额外变慢，现在接受 100ms 以内的真实帧时间，较长停顿继续受限制。战斗画面、按键和模拟跟随浏览器原生刷新节奏；HUD 文字独立限制为每秒 30 次更新，阶段变化立即显示。

哆啦A梦的普通空气炮与后撤炮改为伸直手臂从胸口高度发射，手炮枪口、投射物高度与受击反馈对齐。俯冲炮手臂下压并随枪口向下，左右两侧都保持向下弹道。贴地炮仍能命中蹲姿，普通空气炮可用跳跃规避。

## 渲染优化与检查

- 静态场景按顶点颜色、粗糙度、金属度和自发光合批，保留表面差异。
- 静态场景阴影缓存一次，动态阴影只绘制角色轮廓和互动对象；流畅模式保留静态阴影与角色接触阴影。
- 性能模式把静态阴影过滤从 4 次采样降为 1 次，并关闭动态阴影，减少低端设备每像素的工作量。
- 角色装饰按刚性附着部位合批，骨骼蒙皮共用绘制；命中、蓄力和碎片粒子改为实例化。
- 精细、自动、流畅画质可切换并保存。自动模式只在持续慢帧时降级，避免反复切换带来的抖动。软件渲染默认使用流畅配置。
- 暂停保持当前画面；窗口尺寸变化会重绘。主页预览限制为 30fps。
- 对战每个浏览器帧绘制一次，避免固定 60fps 绘制在 90／144Hz 屏幕产生不均匀间隔。模拟使用最大 1/120 秒子步长，不进行追帧绘制。

同一 Chromium SwiftShader、1280×800 视口、口袋街角待机采样：

| 指标           |     改前 | 改后自动配置 |
| -------------- | -------: | -----------: |
| 主画面绘制调用 |      191 |           72 |
| 主画面三角形   |  261,192 |      159,412 |
| 画布像素       | 1150×574 |      862×430 |

绘制调用减少约 62%，三角形减少约 39%。自动配置在此软件渲染环境会降低分辨率并关闭动态阴影；此表用于比较同一环境的绘制负担，不代表真实显卡帧率，也不是相同画质的 GPU 性能基准。帧耗时受软件驱动调度影响较大，不用于承诺设备帧率。

`npm test` 检查肢长、身体比例、支撑脚、穿地、输入、帧率时间、独立 HUD 更新节奏、枪口对齐和战斗规则；浏览器检查覆盖十种招式、精细／流畅切换后的输入、桌面与窄屏、暂停、胜负和再战。`npm run inspect:motion` 输出每名角色六种姿态，`npm run profile` 输出可重跑的采样 JSON。

## 走路与普攻衔接修正

60fps 限制器原先把每个略高于 16.67ms 的浏览器帧都作为一次重置。当正常刷新交替出现 16.5／16.8ms 时，会丢掉下一帧所需的时间余量。在同一段 600 帧输入中，旧实现只绘制 300 次，修正后绘制 599 次；这是可重复的调度测试，不代表实际显卡始终能达到 60fps。

步态改为带方向的位移驱动，反向走时不会把腿的位置直接翻转。支撑段和摆腿段的横向速度相接，脚在离地与落地时的垂直速度为零。起步、松键与摆臂加入视觉混合，支撑脚持续锁地；超出腿长的地面目标只限制水平距离，避免把脚拉离地面。地图边界前没有位移时，角色会回到待机。

普通直拳／拍击的蓄力、伸出与收手使用连续曲线，最大伸出对应原有命中窗口，回到待机姿势对应收招结束。双方有独立动作路线与原有伤害、前后摇。普攻提前输入扩大为 180ms，便于接下一拳；它不会取消收招，也不会让长按自动连发。

新增回归检查覆盖正常刷新波动、实际走路起停／反向时脚部连续性、接触地面、普攻伸出与回到待机姿势、冷却边界上的提前输入。动作调整只使用现有骨骼与材质，没有增加模型、光源或粒子绘制。

## 原生刷新、起步落脚与特效复用

本轮取消战斗画面的固定 60fps 限制。应用主循环的浏览器检查在模拟 60、90、120、144Hz 时分别绘制 60、90、120、144 次，均推进一秒模拟；此检查隔离 GPU 开销，只验证调度，不代表显卡性能。持续慢于约 52fps 时自动降低画质，不再等到 38fps。

起步第一帧就建立支撑脚锚点，摆腿从实际离地点开始，消除短起步与完整步幅之间的突然跳位。自由脚在世界坐标平滑，空中脚部随身体移动。普攻命中停顿为 28／34ms，冷却为 0.42／0.52 秒；后摇最后 45% 恢复站立地面移动，角色在收拳时衔接步态，攻击和冷却照常完成。

街景树叶细分从 3 降至 2，建筑倒角使用较轻几何，角色模型细节保留。同一软件渲染器、1280×800 视口、862×430 画布、口袋街角待机，主画面三角形从 159,412 降到 108,172（约 32%），绘制调用仍为 72。软件驱动的帧耗时波动较大，本轮采样不能据此承诺真实设备帧率。

命中、蓄力、拖尾和碎片资源按类型、颜色、命中强度复用，缓存最多 24 组；对局销毁会同时释放活跃与缓存资源。连续普攻不再每次销毁同一批 GPU 材质与实例缓冲。浏览器检查验证重复命中特效复用同一对象，直到销毁对局时才释放材质。

`npm run test:experience` 检查双语完整流程、语言持久化、暂停和结算中的切换、对局／画布身份保留、冷却与生命保留、原生刷新节奏、特效复用及 320／390／768px 布局。`npm run inspect:flow` 生成本轮两名角色连续动作视频，包含起停、反向和走路接普攻。
